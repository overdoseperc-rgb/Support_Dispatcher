# Диспетчер заявок службы поддержки

Готовая практическая работа по документу «Большое практическое задание.docx». Все 15 заявок, их названия, приоритеты и порядок вставки перенесены в `INITIAL_REQUESTS` без изменений. Дерево и куча реализованы самостоятельно; используются только стандартные библиотеки Python.

## Запуск и сдача

Требуется Python 3.10 или новее. Распакуйте архив, откройте терминал в папке проекта и выполните:

```text
python main.py
python -m unittest -v
```

`main.py` выполняет все шесть этапов и проверяет контрольные значения через `assert`. Запускайте без флага `-O`, который отключает эти проверки. `test_project.py` содержит дополнительные проверки. `results.txt` — сохранённый вывод программы. Для сдачи в Булгаков загрузите ZIP проекта либо файлы проекта, если форма требует отдельные вложения. `Читай.md` содержит ту же инструкцию.

## Выполнение этапов

1. `Request` хранит `id`, `title`, `priority`; `TreeNode` хранит заявку и двух потомков. `insert` строит BST по `id`. Дубликат отклоняется: дерево и прежняя заявка сохраняются. Исходное дерево выводится по уровням как `ID(приоритет)`.
2. `preorder`, `inorder`, `postorder` реализованы рекурсивно, `levelorder` — с очередью `deque`. Каждый обход возвращает список объектов `Request`. Симметричный обход даёт возрастающие ID: все ключи левого поддерева меньше ключа корня, все ключи правого больше; рекурсивный обход сначала выдаёт левую часть, затем корень и правую часть.
3. Поиск возвращает `(заявка или None, список просмотренных ID)`. Реализованы минимум, максимум, количество узлов и листьев, высота, глубина и `validate_bst`. Высота — число уровней; пустое дерево имеет высоту 0, корень имеет глубину 0. Для отсутствующего ID глубина равна `None`. Проверка BST передаёт строгие нижнюю и верхнюю границы от всех предков, поэтому обнаруживает нарушения внутри поддеревьев и дубликаты.
4. Добавляется `(37, "Утечка данных", 16)`, отклоняется дубликат 50, удаляются 10, 35, 70, выполняется попытка удаления 999. После каждой операции выводятся название, симметричный обход, число узлов, высота и валидность. При двух потомках используется симметричный преемник — минимум правого поддерева; переносится вся заявка. Удаление корня и все граничные случаи дополнительно проверяются тестами.
5. Список `inorder` становится массивом кучи. Ключ — `(priority, id)`, при равенстве приоритетов выше стоит больший ID. `build_max_heap` проходит внутренние узлы снизу вверх, начиная с `len(data) // 2 - 1`. `sift_down` итеративно выбирает большего потомка. Выводятся исходный массив, куча, её уровни и результат `is_max_heap`.
6. `heap_sort` строит max-heap, меняет корень с концом текущей кучи, уменьшает её размер и восстанавливает свойство. Переданный список сортируется **по возрастанию `(priority, id)`**, его объект сохраняется. Второй массив и рекурсия внутри сортировки не создаются. Функция возвращает `None`. Срезы для печати уровней используются только вне сортировки.

## Временная и пространственная сложность

Обозначения: `n` — число узлов/элементов, `h` — высота дерева, `w` — максимальная ширина. Память в таблице дополнительная; выходные списки учтены явно. Само дерево и массив кучи занимают O(n).

| Операция | Время | Дополнительная память |
|---|---|---|
| `insert`, `delete` | O(h) | O(h), рекурсивный стек; новый узел O(1) |
| Построение BST последовательными вставками | O(n log n) при высоте O(log n), O(n²) в худшем случае | O(h) стек + O(n) дерево |
| `search` с путём | O(h) | O(h) для возвращаемого пути |
| `find_min`, `find_max`, `get_depth` | O(h) | O(1) |
| Три рекурсивных обхода | O(n) | O(n) результат + O(h) стек |
| `levelorder` | O(n) | O(n) результат + O(w) очередь |
| Печать дерева по уровням | O(n) | O(w), без учёта длины текста |
| `count_nodes`, `count_leaves`, `height`, `validate_bst` | O(n) | O(h) стек |
| `request_key` | O(1) | O(1) |
| `sift_down` | O(log n) в худшем случае | O(1) |
| `build_max_heap` | O(n) | O(1) |
| `is_max_heap` | O(n) | O(1) |
| `heap_sort` | O(n log n) в худшем случае | O(1) |

BST не балансируется: на произвольном входе h может быть O(n), поэтому поиск, вставка и удаление в худшем случае линейны. Для исходного дерева h = 4. Рекурсивные функции на очень глубоком дереве ограничены пределом рекурсии Python.

Линейное построение кучи объясняется тем, что большинство узлов расположены близко к листьям: сумма затрат на просеивания ограничена O(n). Сортировка делает O(n) извлечений с просеиванием O(log n), поэтому получает O(n log n). Она не является стабильной; порядок равных приоритетов определяется ID. Оценки предполагают O(1) сравнение числовых ключей.

В тестах `sorted` используется исключительно как независимый эталон; в реализации дерева, кучи и сортировки встроенная сортировка и `heapq` не используются.
